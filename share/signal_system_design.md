# 信号系统设计

> 本文档是信号系统的权威设计。从投资认知出发，定义信号系统"是什么、为什么、怎么运作"。
> 技术实现文档（`signal_implementation_design.md`）从属于本文档。
> 供专家审阅，确认后进入技术设计和开发。

---

## 一、信号系统的定位

### 1.1 当前系统的决策现状

一笔完整的交易有五个决策环节：

```
择股（买什么）→ 择时（什么时候买）→ 仓位（买多少）→ 持仓管理（持有中怎么应对）→ 离场（什么时候卖、怎么卖）
```

当前系统对这五个环节的覆盖：

| 环节 | 当前状态 | 问题 |
|------|---------|------|
| 择股 | ✅ 有信号（A 缩量回踩 / B 箱体突破 / C V反N字） | 只覆盖右侧趋势，没有打板/竞价/尾盘 |
| 择时 | ⚠️ 部分覆盖（市场天气+板块强度+前置过滤） | 只过滤"不该买"，没有主动判断"现在该不该动" |
| 仓位 | ✅ 有（risk_sizing 三步法） | 可用，但与信号脱节——不管什么信号统一计算 |
| 持仓管理 | ❌ 缺失 | 加仓/减仓/调止损/调仓全靠人工或固定规则 |
| 离场 | ❌ 缺失 | 只有硬止损兜底（-5%/-8%），没有趋势破位/滞涨/板块退潮等主动卖出判断 |

**核心问题：系统只解决了"什么时候买"，没有解决"买完之后怎么办"和"什么时候卖"。**

这违反了投资认知的三条根基：
- 认知 6「止损是成本，不是失败」→ 当前止损是被动触发的固定规则，没有主动判断
- 认知 8「赚大钱靠少数几笔」→ 没有移动止盈信号，好不容易抓到一笔趋势股，不知道什么时候该放手让利润奔跑
- 认知 4「不是每天都要交易」→ 系统不会告诉你"今天该持有不动"，只在有买入机会时才有声音

### 1.2 信号系统应该是什么

信号系统是整个投资助手的**决策中枢**——它对交易的每一个环节、每一天的每一个时刻，都有明确的判断输出：

- 该买 → 买什么、因为什么
- 该卖 → 卖什么、因为什么
- 该调 → 调什么、因为什么
- 什么都不该做 → 为什么不做

**没有信号覆盖的决策点，就是系统的盲区。盲区里的决策只能靠人工，而人工意味着情绪、犹豫、侥幸。**

信号系统的终极目标：**让"人工判断"的空间趋近于零。** 不是取消人工，而是让每个需要人工判断的点都有系统信号作为参考基准。有了基准才有纪律，有了纪律才能复盘，有了复盘才能进化。

### 1.3 信号 ≠ 操作

当前系统的另一个问题是**信号和操作混在一起**——信号触发后直接买入影子账户，中间没有"操作指令"层。

这导致：
- 信号只回答"该不该做"，不回答"具体怎么做"
- 无法单独评价"判断对不对"（信号质量）和"执行好不好"（操作质量）
- 同一个信号在不同账户状态下应该有不同的操作（满仓时和空仓时同一信号的应对截然不同），但当前无法区分

所以新的信号系统必须拆成两层：**信号层**（判断做什么）+ **操作层**（决定怎么做）。

## 二、设计原则

从十条投资认知推导信号系统的设计原则：

| 认知 | 推导出的设计原则 |
|------|---------------|
| 1 A股短线是情绪博弈 | 信号必须能感知情绪周期，不同情绪阶段激活不同信号 |
| 2 政策是最大Alpha | 信号体系预留政策/消息驱动的紧急通道（X7 紧急卖出） |
| 3 流动性决定策略上限 | 市场天气是所有信号的前置门控，弱市不产出买入信号 |
| 4 不是每天都要交易 | "不做"也是一种信号（IDLE），系统必须主动输出"今天不操作" |
| 5 仓位 > 选股 | 仓位类信号（加仓/减仓/调仓）不是选股的附属品，是独立的信号类型 |
| 6 止损是成本 | 止损不是"兜底规则被动触发"，而是"信号主动判断" |
| 7 连续亏损是正常的 | 连亏后系统不停机，而是产出 P8 强平信号 + IDLE 信号 |
| 8 赚大钱靠少数几笔 | P3 调止损位（移动止盈）是核心信号，让利润奔跑 |
| 9 对手是和你一样的散户 | 信号触发条件利用散户行为模式（追涨杀跌、锚定效应） |
| 10 系统 > 纪律 > 技术 > 消息 | 信号是"系统"，操作是"纪律"，两层分开考核，用规则替代判断 |

**核心原则：交易的每一个决策环节，系统都有信号输出。人可以否决信号，但不应该在没有信号的情况下做决策。**

## 三、四层架构

```
┌─────────────────────────────────────────────────┐
│  市场数据（K线/行情/板块/资金/情绪/消息）          │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  信号层（做什么）                                  │
│  输入：市场数据 + 持仓状态                         │
│  输出：信号产物（方向/标的/理由/信心度/有效期）      │
│  职责：判断，不执行                                │
│  20 个信号类型，覆盖交易全生命周期                  │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  操作层（怎么做）                                  │
│  输入：信号产物 + 账户状态 + 风控规则               │
│  输出：操作指令（价格/数量/委托方式/执行窗口）       │
│  职责：翻译信号为可执行的操作，不改变方向            │
│  硬约束：操作层不可改方向 / 卖出优先于买入           │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  执行层（做了没）                                  │
│  影子账户：所有信号自动执行，积累样本               │
│  真实账户：用户自主决定是否跟随                     │
└──────────────────┬──────────────────────────────┘
                   ↓
┌─────────────────────────────────────────────────┐
│  考核层（做得对不对）                              │
│  信号考核：准确率 / 胜率 / 期望收益                 │
│  操作考核：执行偏差 / 滑点 / 时机质量               │
│  分开评估，互不混淆                                │
└─────────────────────────────────────────────────┘
```

### 3.1 层间边界（铁律）

| 边界 | 规则 | 原因 |
|------|------|------|
| 信号层 → 操作层 | 信号只传方向/标的/信心度，**不传价格和数量** | 信号回答"做不做"，操作回答"怎么做"。如果信号也决定价格，两层的职责就混了 |
| 操作层 → 执行层 | 操作层只传指令，**不知道执行结果** | 如果操作层等执行结果再决定下一步，就变成了交易引擎而非指令层 |
| 操作层不可改方向 | 信号说"卖出"，操作层只能决定卖多少、什么价、什么时候，**不能翻转为"不卖"或"买"** | 方向归判断层（信号），执行归操作层，边界不可逾越 |
| 卖出优先于买入 | 同一时刻同时触发卖出和买入信号，**卖出必须先处理** | 投资认知 5：仓位 > 选股。先保命再进攻 |
| 硬止损独立于信号层 | -5% 减半 / -8% 清仓在信号层之外独立运行 | 信号层可能因为数据缺失/程序错误而漏判。硬止损是最后一道防线，不允许单点故障 |

## 四、信号体系：20 个信号类型

### 4.1 交易全生命周期覆盖

一笔交易从发现机会到最终离场，中间可能经历以下状态转换：

```
发现机会 → 建仓 → 持有 → {加仓/减仓/调止损/换仓/调仓} → 离场
   ↑                                                      ↓
   └──────────────── 资金释放，寻找下一个机会 ←─────────────┘
```

20 个信号类型按交易生命周期分为四组：

| 生命周期阶段 | 信号组 | 类型数 | 覆盖的决策点 |
|-------------|--------|--------|------------|
| 发现+建仓 | 买入信号 E1-E5 | 5 | 右侧趋势/突破/反转/打板/竞价尾盘接力 |
| 持有→离场 | 卖出信号 X1-X8 | 8 | 趋势破位/滞涨/板块退潮/止损/止盈/时间止损/紧急/竞价卖出 |
| 持有中管理 | 仓位信号 P1-P3,P6-P8 | 6 | 加仓/减仓/调止损/换仓/调仓/强平 |
| 全程 | IDLE | 1 | 不操作也是一种决策 |

### 4.2 买入信号（Entry Signals）— 5 类

买入信号回答"**该不该建仓，为什么**"。

#### E1 趋势回踩买入

- **交易逻辑**：均线多头排列确认趋势向上，股价缩量回踩均线是"上车点"——主力不出货（缩量），散户被洗出去，回踩结束后继续上涨。
- **适用场景**：趋势模式，修复/发散/高潮期。
- **触发本质**：趋势完好 + 短期回调 + 主力未离场。
- **信号输出**：标的、回踩均线位置、缩量程度、建议入场价、几何止损价。
- **对应方法论**：择股四要素中的"形态"（均线多头首次回踩）+ 择时五要素中的"缩量"。
- **现有实现**：detector_a（信号 A），保持不变。

#### E2 突破买入

- **交易逻辑**：长期横盘整理后的放量突破，意味着筹码充分换手、多空达成新共识、主力开始拉升。突破点是趋势的起点。
- **适用场景**：趋势模式，修复/发散期。
- **触发本质**：横盘蓄力完成 + 放量突破确认 + 无假突破特征。
- **信号输出**：标的、箱体上沿、突破幅度、量比、建议入场价、几何止损价。
- **对应方法论**：择股四要素中的"形态"（突破平台/前高）。
- **现有实现**：detector_b（信号 B），保持不变。

#### E3 反转买入

- **交易逻辑**：超跌后 V 反弹确认底部，回踩不破低点，再次突破 V 反高点形成 N 字形态——这是最强的底部反转信号。
- **适用场景**：趋势模式，冰点修复期尤为有效。
- **触发本质**：跌到位 + 反弹确认底 + 二次上攻确认反转。
- **信号输出**：标的、V 反高点、回踩低点、突破幅度、量比。
- **对应方法论**：择股四要素中的"形态"（底部放量阳线突破短期均线）。
- **现有实现**：detector_c（信号 C），保持不变。

#### E4 打板买入

- **交易逻辑**：涨停是 A 股特有的稀缺性机制。强势涨停（封单坚决、板块共振、首板/二板位置）意味着主力高度控盘，次日有溢价预期。打板买入赚的是"次日溢价"这个期权。
- **适用场景**：连板模式，发散/高潮期。冰点/退潮期绝不打板。
- **触发本质**：涨停确认主力意图 + 封单强度确认筹码锁定 + 板块共振确认不是孤军。
- **信号输出**：标的、涨停时间、封单强度、板块共振度、板位（首板/二板）。
- **对应方法论**：模式切换标准（高潮期连板模式为主）+ 择股四要素中的"股性"（有连板历史）。
- **现有实现**：无，新增。

#### E5 短期买点确认

- **交易逻辑**：已锁定标的（在自选池中有预期），在特定时间窗口确认买点。不是独立发现机会，而是确认"预期中的机会是否兑现"。
- **三个子模式**：
  - **竞价确认**：竞价量价异动 + 预期验证 → 竞价/开盘买入
  - **尾盘确认**：尾盘承接有力 + 次日预期强 → 尾盘买入
  - **次日接力**：昨日强势 + 今日开盘确认 → 开盘买入
- **适用场景**：均适用于趋势模式和连板模式，取决于标的。
- **触发本质**：预期体系的兑现确认——昨天建立了预期，今天数据确认预期成立。
- **信号输出**：标的、时间窗口、预期验证结果。操作层决定具体是竞价/尾盘/次日开盘。
- **对应方法论**：预期体系（超预期/符合预期 → 操作，不及预期 → 放弃）。
- **现有实现**：无，新增。

### 4.3 卖出信号（Exit Signals）— 8 类

卖出信号回答"**该不该离场，因为什么**"。

这是当前系统**最大的盲区**——只有硬止损兜底，没有主动判断卖出。而实际交易中，卖出的决策维度比买入更多、更复杂。

#### X1 趋势破位卖出

- **交易逻辑**：均线是趋势的骨架。收盘跌破关键均线 + 放量确认 = 趋势结束。板块走弱是辅助验证——个股破位如果同时板块退潮，趋势结束的概率更高。
- **对应认知**：认知 10（用规则替代判断）——不要"再看看"，趋势破了就是破了。
- **与硬止损的区别**：X1 基于技术分析主动判断，可能在成本价附近就触发（比如买入后横盘然后破位，没亏但趋势没了）；硬止损是价格触发的被动规则。

#### X2 滞涨卖出

- **交易逻辑**：价格到了高位但涨不动了——量能萎缩（没人愿意高位接盘）、价格不创新高（上攻动力耗尽）、RSI 回落（超买修正）。滞涨是主力出货的前兆。
- **对应认知**：认知 8（赚大钱靠少数几笔，但也要知道什么时候收手）+ 认知 9（散户在高位追涨接盘，主力在高位派发）。
- **适用条件**：有一定浮盈的持仓。亏损中的持仓不适用（那不是"滞涨"，是"没涨起来"）。

#### X3 板块退潮卖出

- **交易逻辑**：A 股的短线行情是板块驱动的。板块退潮后，即使个股短期还在涨，资金也会逐步撤离——"皮之不存，毛将焉附"。板块排名从前 30% 滑落到后 50%，且个股跑输板块，该走。
- **对应认知**：认知 1（A 股短线是情绪博弈）——板块轮动是情绪轮动的映射。
- **对应方法论**：择时五要素中的"板块"——只做涨幅前 3 板块，板块退出前 3 就不做了。

#### X4 止损触发

- **交易逻辑**：价格触及止损线，无条件执行。止损是交易成本，不是失败。
- **智能止损 vs 硬止损**：
  - X4 使用买入信号的几何止损价（A 信号的 MA × 0.99，B 信号的箱体上沿 × 0.98），通常在 -2%~-4% 之间触发。
  - 硬止损（-5%/-8%）是独立兜底，在 X4 之外运行。
  - 两者并行：X4 是"智能护盾"，硬止损是"铁底"。
- **对应认知**：认知 6（止损是成本，不是失败）+ 认知 10（用规则替代判断）。

#### X5 止盈触发

- **交易逻辑**：让利润奔跑，但不能坐过山车。三种止盈机制：
  - **目标位止盈**：达到预设目标位（3R）
  - **移动止盈**：高点回撤超过阈值
  - **MA 级止盈**：浮盈达标后止盈线跟随均线（盈利 ≥10% 跟 MA10，≥20% 跟 MA5）
- **对应认知**：认知 8（赚大钱靠少数几笔 = 让盈利奔跑）。
- **与 P3 的关系**：P3 是"上调止盈线"（动作是调止损位），X5 是"止盈线被触发"（动作是卖出）。P3 先走，X5 后走。

#### X6 时间止损

- **交易逻辑**：持仓 N 天了还没盈利——说明建仓判断可能有误，或者市场环境变了。资金有时间成本，不能被一只不动的股票占着。
- **对应认知**：认知 4（不是每天都要交易）的推论——也不是每只股票都值得一直拿着。
- **设计要点**：
  - 持仓超过 N 天 + 浮盈未达阈值 → 触发
  - 但如果近期突然放量启动（可能是新一波开始），不触发——避免"黎明前倒下"
- **专家特别要求**：提前到第一期落地，"僵尸仓"是资金浪费。

#### X7 紧急卖出

- **交易逻辑**：黑天鹅事件 / 异常暴跌 / 跌停打开。不分析原因，不等确认，先跑为敬。
- **触发场景**：
  - 当日跌幅超限（异常暴跌）
  - 浮亏触及一期兜底线（-8%）
  - 重大利空（预留，Phase 1 暂不做消息触发）
- **对应认知**：认知 6（止损是成本）+ 认知 7（连续亏损是正常的，但单笔要控制）。

#### X8 竞价卖出

- **交易逻辑**：集合竞价是"预期兑现"的第一个窗口。竞价低开超预期（放量低开）+ 昨日已有弱势信号 = 预期落空，不等开盘直接在竞价阶段卖出。
- **对应方法论**：预期体系（不及预期 → 出局，不犹豫）。
- **执行窗口**：集合竞价（9:15-9:25 挂单），这是所有信号中唯一一个必须在竞价阶段处理的。

### 4.4 仓位管理信号（Position Signals）— 6 类

仓位管理信号回答"**持仓中该怎么调整**"。

#### P1 加仓

- **交易逻辑**：首仓买入后走势符合或超预期 → 加仓剩余 50%。这是方法论中"先买一半验证判断，确认后再加"的系统化实现。
- **触发本质**：趋势加速确认 + 仓位未满 + 风控允许。
- **对应方法论**：单票仓位（首仓 50%，走势确认后加剩余 50%）。
- **注意**：亏损中绝不加仓（铁律）。

#### P2 减仓

- **交易逻辑**：风险升高但还没到清仓条件——先减一半，降低风险敞口。三种场景：
  - 部分止盈（涨到一定程度先落袋一半）
  - 风险升高（黄灯/橙灯预警，还没到红灯）
  - 硬止损减半（浮亏 -5%，减半仓保留观察）
- **对应方法论**：分仓管理（不是"全进全出"，而是梯度操作）。

#### P3 调止损位

- **交易逻辑**：价格上涨后把止损线上移——这是"让利润奔跑"的机械实现。三个阶段：
  1. 盈利达 1.5R → 止损上移到成本（保本）
  2. 盈利达 10% → 止损上移到 MA10（锁定趋势）
  3. 盈利达 20% → 止损上移到 MA5（锁定加速段）
- **核心原则**：止损只能上调，不能下调。
- **对应认知**：认知 8（赚大钱靠少数几笔）——P3 是让这"少数几笔"能真正赚到大钱的关键机制。
- **与 X5 的协作**：P3 上调止损位 → X5 检测止盈触发。P3 是"设线"，X5 是"触线"。

#### P6 换仓

- **交易逻辑**：持仓股弱于候选股——不是因为持仓股不好，而是有更好的机会。换仓是"机会成本"的操作化。板块轮动时尤其重要——旧板块退潮，新板块崛起，持仓应该跟着轮动。
- **操作特殊性**：产出两条操作指令——先卖旧股，再买新股。
- **高风险提示**：换仓是双向操作，判断错误会"两头亏"。建议影子账户自动执行，真实账户人工确认。

#### P7 调仓

- **交易逻辑**：组合层面的再平衡。某只股涨多了导致占比超限（>25%）、总仓位超限（>80%），需要机械性地减持超配部分。
- **触发本质**：不是"这只股不好"，而是"占比太高，风险集中"。
- **对应认知**：认知 5（仓位 > 选股）。

#### P8 强平

- **交易逻辑**：风控铁律被触发——当日亏损 ≥3% 或连亏 ≥3 笔。强制减仓，保护本金。
- **与情绪熔断的关系**：P8 触发"立即减仓"动作 → 情绪熔断自动激活"暂停 2 天不开新仓"。P8 是因（动作），熔断是果（状态）。
- **对应认知**：认知 7（连续亏损是正常的，但要控制节奏）。

### 4.5 IDLE — 1 类

- **交易逻辑**：所有检测器跑完，没有任何信号触发 → 系统主动输出"今天不操作"。
- **三种原因**：
  - `market_weak`：市场天气弱市/情绪熔断，系统性空仓
  - `hold_steady`：持仓趋势完好，无操作条件，安心持有
  - `cash_mgmt`：空仓+大量闲置资金，提示逆回购/货基
- **对应认知**：认知 4（不是每天都要交易）——"不做"是最重要的决策之一。

### 4.6 信号之间的关系

20 个信号不是孤立的，它们之间有明确的关系：

**互斥关系**（同一标的同一时刻最多只产出一个）：
- E1/E2/E3/E4/E5 互斥——同一只股不会同时触发两种买入信号（取信心度最高的）
- X1/X2/X3 互斥——同一只股的卖出原因只取主因

**协作关系**（一个信号为另一个铺路）：
- P3 → X5：P3 上调止盈线，X5 检测止盈触发
- E1-E5 → P1：买入信号建仓后，P1 检测加仓条件
- X4/X5/X6/X7/X8 → IDLE：卖出后释放资金，IDLE 判断是否做现金管理

**优先级关系**（冲突时的裁决顺序）：
1. P8 强平（风控铁律，最高优先）
2. X7 紧急卖出（黑天鹅，第二优先）
3. X4 止损触发（止损不犹豫）
4. X5 止盈触发
5. X1/X2/X3/X6/X8 主动卖出
6. P2 减仓
7. P3 调止损位
8. P7 调仓
9. P1 加仓
10. E1-E5 买入
11. P6 换仓
12. IDLE

**核心规则：卖出类信号永远优先于买入类信号。**

## 五、操作层设计

### 5.1 操作层的职责

信号层说"卖出 001299"，操作层回答：
- **什么方式**：限价/市价/竞价
- **什么价格**：具体挂多少钱
- **多少数量**：卖全部还是卖一半
- **什么时候**：现在/尾盘/明天开盘
- **预埋什么**：止损价/止盈价

### 5.2 信号类型 → 操作映射

| 信号 | action | order_type | 数量逻辑 | 执行窗口 |
|------|--------|-----------|---------|---------|
| E1 趋势回踩 | buy | limit | risk_sizing 三步法 | 尾盘/次日开盘 |
| E2 突破 | buy | market | risk_sizing 三步法 | 盘中（不等，突破要追） |
| E3 反转 | buy | limit | risk_sizing 三步法 | 尾盘/次日开盘 |
| E4 打板 | buy | limit(涨停价) | risk_sizing 三步法 | 盘中（排板） |
| E5 短期确认 | buy | limit/auction | risk_sizing 三步法 | 竞价/尾盘/次日开盘（由子模式决定） |
| X1 趋势破位 | sell | limit | 全仓 | 尾盘/次日开盘 |
| X2 滞涨 | sell | limit | 全仓或减半 | 尾盘 |
| X3 板块退潮 | sell | limit | 全仓 | 尾盘 |
| X4 止损 | sell | market | 全仓 | 盘中（即刻） |
| X5 止盈 | sell | limit | 全仓或减半 | 盘中/尾盘 |
| X6 时间止损 | sell | limit | 全仓 | 尾盘 |
| X7 紧急卖出 | sell | market | 全仓 | 盘中（即刻） |
| X8 竞价卖出 | sell | auction | 全仓 | 竞价 |
| P1 加仓 | buy | limit | 当前仓位的 50% 以内 | 回踩确认后 |
| P2 减仓 | sell | limit | 30%-50% | 盘中/尾盘 |
| P3 调止损 | adjust_stop | — | — | — |
| P6 换仓 | sell+buy | limit | 卖全仓，买按 risk_sizing | 盘中 |
| P7 调仓 | sell | limit | 超配部分 | 尾盘 |
| P8 强平 | sell | market | 减半仓 | 盘中（即刻） |
| IDLE | idle | — | — | — |

### 5.3 硬约束执行

操作引擎在生成操作指令时，强制执行两条硬约束：

1. **方向校验**：信号 direction=sell → action 只能是 sell，不能是 buy。校验不通过直接报错，不生成指令。
2. **优先级排序**：多条信号同时产出时，按 §4.6 优先级排序，卖出指令排在买入指令前面。

### 5.4 操作指令的生命周期

```
生成 → 待执行 → 已执行/已过期/已取消
```

- **生成**：操作引擎收到信号后立即生成
- **待执行**：有效期内等待执行窗口到来
- **已执行**：在影子账户/真实账户中成交
- **已过期**：超过 `valid_until` 未执行，自动作废
- **已取消**：更高优先级的信号覆盖了这条指令（如先产出 P1 加仓，随后 X4 止损触发，P1 取消）

## 六、信号的运行节奏

### 6.1 两条扫描管线

信号系统运行时分两条管线：

| 管线 | 作用 | 扫描范围 | 频率 |
|------|------|---------|------|
| **管线 A：入池扫描** | 在全市场中发现买入机会 | 全 A 成交额 > 1 亿（~2000-3000 只） | 盘后 15:35 + 盘中 15 分钟 |
| **管线 B：持仓扫描** | 对现有持仓检测卖出/管理信号 | 当前持仓（1-4 只） | 盘中 15 分钟 + 14:55 强扫 + 9:25 竞价 |

**为什么要分两条**：
- 买入扫描要看几千只股票，计算量大，频率不能太高
- 持仓扫描只看 1-4 只股票，极轻量，可以更频繁
- 卖出信号的时效性 > 买入信号（错过一个买点还有下一个，错过一个卖点可能亏更多）

### 6.2 每日时间线

```
07:50  同源对账（现有 cron）
09:00  盘前提醒（现有推送）
09:25  管线 B — 竞价扫描（X8 竞价卖出 + E5 竞价确认）
09:35  开盘快报（现有推送）
09:45  管线 B — 首次盘中扫描
10:00  管线 B
  :     ... 每 15 分钟一次 ...
11:30  午间休市
13:00  管线 B — 午后首次扫描
  :     ... 每 15 分钟一次 ...
14:55  管线 B — 尾盘强扫（所有尾盘执行窗口的操作在此确认）
15:00  收盘
15:35  管线 A — 入池扫描（E1-E5 全市场扫描）
15:35  管线 B — 盘后扫描（基于收盘价的信号确认）
16:00  复盘（现有推送）
```

### 6.3 信号的有效期

| 信号类型 | 有效期 | 原因 |
|---------|--------|------|
| X4 止损 / X7 紧急 / P8 强平 | 即时（触发即执行） | 风控不等待 |
| X8 竞价卖出 | 当日竞价阶段 | 过了竞价就没意义了 |
| X1/X2/X3/X5/X6 卖出 | 当日收盘前 | 卖出信号当日有效 |
| E1/E2/E3/E4 买入 | 次日收盘前 | 盘后发现的买入机会给一个交易日窗口 |
| E5 短期确认 | 当日对应窗口 | 竞价/尾盘/开盘各有时间窗 |
| P1/P2/P3/P6/P7 仓位管理 | 当日收盘前 | 仓位调整当日完成 |
| IDLE | 下次扫描前 | 每次扫描重新判断 |

## 七、考核体系

### 7.1 信号考核（判断对不对）

**核心指标**：信号触发后 N 日内，标的是否沿预期方向运动。

| 信号方向 | 考核标准 | 好的信号 |
|---------|---------|---------|
| 买入信号 | 触发后 5 日最大涨幅 | > 5% 优秀 / > 0 合格 |
| 卖出信号 | 触发后 5 日最大跌幅 | < -3% 优秀（卖对了） |
| 加仓信号 | 加仓后 5 日涨幅 | > 3% 优秀 |
| 减仓信号 | 减仓后 5 日跌幅 | < -2% 优秀（减对了） |
| IDLE | 无操作期间大盘涨幅 | < 2%（没错过大涨）|

**分类统计**：
- 按信号类型（E1/E2/E3...）分别统计，发现哪类信号准确率最高
- 按市场天气（强势/震荡/弱势）分组，发现信号在什么环境下最有效
- 按板块/个股特征分组，发现信号的适用范围

### 7.2 操作考核（执行好不好）

**核心指标**：操作指令 vs 实际执行的偏差。

| 指标 | 计算方式 | 好的操作 |
|------|---------|---------|
| 价格偏差 | (实际成交价 - 计划价) / 计划价 | < 0.5% |
| 时机偏差 | 实际执行时间 vs 计划执行窗口 | 在窗口内 |
| 数量偏差 | 实际成交量 / 计划数量 | 100% |
| 滑点 | 委托价 vs 成交价 | < 0.3% |

### 7.3 考核分离原则

**信号准确但操作差**：信号说"该卖了"且后来确实跌了（信号对），但执行太慢/挂价太高导致没卖出（操作差）→ 改进操作层。

**信号不准但操作好**：信号说"该卖了"但后来反而涨了（信号错），执行了卖出且成交快（操作好）→ 改进信号层。

**绝不能混在一起考核**——否则无法定位问题出在判断还是执行。

### 7.4 与七期参数寻优的兼容

- **买入信号（E1-E4）**：走七期已有的三阶段参数寻优体系
- **E5 及其他 16 类信号**：等 Phase B 积累真实交易数据后再设计考核体系
- 初期的考核以"信号触发后 N 日走势"为主，不做参数优化

## 八、风控集成

### 8.1 三层风控架构

```
第一层：信号层风控
  市场天气弱市 → 不产出买入信号
  情绪熔断激活 → 不产出买入信号
  仓位已满 → 不产出买入信号（P1 加仓也不触发）

第二层：操作层风控
  单股 > 25% → 操作层拒绝生成买入指令
  总仓位 > 80% → 操作层拒绝生成买入指令
  持仓 > 4 只 → 操作层拒绝生成买入指令

第三层：硬止损兜底（独立于信号层）
  浮亏 ≥ 5% → 减半仓（不依赖任何信号）
  浮亏 ≥ 8% → 清仓（不依赖任何信号）
  当日亏损 ≥ 3% → 停手
  连亏 ≥ 3 笔 → 停手
```

### 8.2 信号层与硬止损的并行关系

```
价格下跌
  ↓
  ├── X4 智能止损检测（结合趋势/板块/量能判断）
  │     可能在 -2%~-4% 就触发 → 操作层生成卖出指令
  │
  └── 硬止损检测（纯价格规则，独立运行）
        -5% → 减半仓
        -8% → 清仓

  如果 X4 先触发 → 执行卖出 → 硬止损不再触发（已经卖了）
  如果 X4 未触发（数据缺失/程序异常）→ 硬止损兜底
  硬止损 > X4，硬止损永远是最后防线
```

## 九、落地路径

### Phase A-1：补全卖出 + 止损体系（最紧迫）

**目标**：让系统不再是"只会买不会卖"。

| 信号 | 优先级理由 |
|------|-----------|
| X1 趋势破位 | 趋势模式的核心离场判断，当前完全缺失 |
| X4 止损触发 | 现有规则升级为信号，有逻辑基础 |
| X5 止盈触发 | 移动止盈 + 目标位止盈，让利润奔跑的关键 |
| X6 时间止损 | 清除"僵尸仓"，释放资金。专家要求提前 |
| P3 调止损位 | 移动止盈的"设线"端，与 X5 配合 |
| IDLE | "不做"也要有信号 |

### Phase A-2：完善买入 + 仓位管理

| 信号 | 优先级理由 |
|------|-----------|
| E5 短期买点确认 | 竞价/尾盘/接力的时间窗口确认 |
| P1 加仓 | 方法论中"首仓 50% + 确认后加仓"的系统化 |
| P2 减仓 | 梯度离场，不再"全进全出" |

### Phase A-3：高级策略

| 信号 | 优先级理由 |
|------|-----------|
| E4 打板买入 | 连板模式的核心，需要实时盘口数据支撑 |
| P6 换仓 | 板块轮动跟随，双向操作风险高 |
| P7 调仓 | 组合层面再平衡 |

### 未排期

| 信号 | 原因 |
|------|------|
| X2 滞涨 | 判断标准主观性强，需更多数据验证 |
| X3 板块退潮 | 依赖板块排名的持续跟踪，数据链路需完善 |
| X7 紧急卖出 | 价格触发部分简单（Phase A-1 可做），消息触发部分待定 |
| X8 竞价卖出 | 依赖竞价数据的稳定性，需验证 |
| P8 强平 | 逻辑简单但影响大，需谨慎上线 |
