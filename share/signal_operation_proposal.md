# 信号与操作双层架构方案

> 供专家评审，待反馈后落地。

## 一、问题

当前信号系统只有 3 个买入信号（A 缩量回踩 / B 箱体突破 / C V反N字），且信号和操作混在一起——信号触发后直接写影子账户，中间没有独立的"操作指令"层。

结果：
- 买入以外的动作（卖出/加仓/做T/调仓...）全靠固定规则或人工判断
- 信号只回答"该不该做"，不回答"具体怎么做"
- 无法对操作执行质量单独考核

## 二、目标架构：信号层 + 操作层

```
市场数据 → 【信号层】检测条件 → 信号产物（做什么）
                                    ↓
                              【操作层】生成指令 → 操作指令（怎么做）
                                    ↓
                              【执行层】模拟/真实成交
                                    ↓
                              【考核层】信号准确率 + 操作执行质量 分开评估
```

### 信号层职责
- 输入：K线、量价、均线、板块、资金、情绪等市场数据
- 输出：**信号产物**（signal）
  - 信号类型（买入/卖出/加仓/减仓/做T/调仓/空仓...）
  - 触发标的
  - 触发理由
  - 信心度（基于历史胜率）
  - 有效期（过期作废）
- 不关心：价格、数量、委托方式

### 操作层职责
- 输入：信号产物 + 账户状态 + 风控规则
- 输出：**操作指令**（operation）
  - 委托方式（限价/市价/条件单）
  - 委托价格
  - 委托数量（股数）
  - 执行窗口（竞价/开盘/盘中/尾盘）
  - 止损预埋价
  - 止盈预埋价
  - 有效期
- 不关心：为什么要做（信号层已决定）

## 三、24 个原子操作 → 信号类型映射

基于专家穷举的 24 个原子操作，归纳为以下信号类型：

### 买入信号（Entry Signals）

| 信号 | 触发条件（待设计） | 对应原子操作 |
|------|-------------------|-------------|
| **E1 趋势回踩买入** | 现有信号 A（均线多头缩量回踩） | 限价买入、分批加仓 |
| **E2 突破买入** | 现有信号 B（箱体放量突破） | 市价买入、抢筹单 |
| **E3 反转买入** | 现有信号 C（V反N字） | 限价买入 |
| **E4 打板买入** | 涨停封单强度 + 板块共振 + 首板/二板 | 涨停排板、扫板 |
| **E5 竞价买入** | 竞价量价异动 + 预期验证 | 集合竞价买入 |
| **E6 尾盘买入** | 尾盘承接 + 次日预期强 | 尾盘买入 |
| **E7 接力买入** | 前日强势 + 次日低开/平开确认 | 次日开盘限价买入 |

### 卖出信号（Exit Signals）

| 信号 | 触发条件（待设计） | 对应原子操作 |
|------|-------------------|-------------|
| **X1 趋势破位卖出** | 跌破关键均线 + 放量 + 板块走弱 | 限价卖出 |
| **X2 滞涨卖出** | 高位缩量 + 上攻乏力 + 量价背离 | 限价卖出 |
| **X3 板块退潮卖出** | 所属板块连续走弱 + 个股补跌信号 | 限价卖出、尾盘卖出 |
| **X4 止损触发** | 价格触及止损线（现有规则升级为信号） | 市价卖出 |
| **X5 止盈触发** | 达到目标位 / 移动止盈回撤 | 限价卖出 |
| **X6 时间止损** | 持有 N 日无盈利 | 尾盘卖出 |
| **X7 紧急卖出** | 重大利空 / 黑天鹅 / 跌停打开 | 市价卖出、跌停排队 |
| **X8 竞价卖出** | 竞价低开超预期 + 昨日弱势 | 集合竞价卖出 |

### 仓位管理信号（Position Signals）

| 信号 | 触发条件（待设计） | 对应原子操作 |
|------|-------------------|-------------|
| **P1 加仓** | 持仓盈利 + 趋势加速确认 + 仓位未满 | 分批加仓 |
| **P2 减仓** | 部分止盈 / 风险升高但未达清仓条件 | 分段减仓 |
| **P3 调止损位** | 价格上移后上调止损线（移动止盈核心） | 上调止损/止盈位 |
| **P4 做T（正T）** | 盘中回调到支撑 → 买入 → 反弹后卖昨仓 | T+0 先买后卖 |
| **P5 做T（反T）** | 盘中冲高到压力 → 卖昨仓 → 回落后买回 | T+0 先卖后买 |
| **P6 换仓** | 持仓股弱于候选股 + 板块轮动信号 | 卖A + 买B |
| **P7 调仓** | 组合偏离目标比例 + 风险再平衡 | 仓位再平衡 |
| **P8 强平** | 风控铁律触发（日亏3%/连亏3笔） | 强制减仓 |

### 空仓信号（Idle Signals）

| 信号 | 触发条件（待设计） | 对应原子操作 |
|------|-------------------|-------------|
| **I1 空仓观望** | 市场天气弱市 / 情绪熔断 / 无合格信号 | 空仓观望 |
| **I2 持有不动** | 趋势完好 + 无卖出信号 + 无加减仓条件 | 持有观望 |
| **I3 现金管理** | 空仓/半仓时，闲置资金 > 阈值 | 逆回购/货基 |

## 四、操作指令结构（operation）

每个信号触发后，操作层生成一条操作指令：

```python
{
    # 来源
    "signal_id": "uuid",           # 关联的信号
    "signal_type": "E1",           # 信号类型
    
    # 操作
    "action": "buy",               # buy/sell/adjust_stop/t_buy/t_sell/rebalance/idle
    "order_type": "limit",         # limit/market/auction/conditional
    "price": 14.34,                # 委托价格（市价单为 None）
    "quantity": 2000,              # 委托股数
    "code": "001299",
    
    # 时机
    "execution_window": "intraday_tail",  # auction/open/intraday/intraday_tail/next_open
    "valid_until": "2026-04-29 15:00",    # 有效期
    
    # 风控预埋
    "stop_loss_price": 13.62,      # 止损预埋
    "take_profit_price": 17.20,    # 止盈预埋
    
    # 元数据
    "priority": "normal",          # urgent/normal/low
    "reason": "信号A触发，MA20回踩企稳",
    "created_at": "2026-04-28 15:35:00",
}
```

## 五、落地优先级

按频率和价值排序，建议分三期：

### 第一期：补全卖出（最紧迫）
- X1 趋势破位卖出
- X4 止损触发（现有规则升级为信号）
- X5 止盈触发（现有规则升级为信号）
- P3 调止损位
- I2 持有不动

### 第二期：完善买入 + 仓位管理
- P1 加仓
- P2 减仓
- E5 竞价买入
- E6 尾盘买入
- P4/P5 做T

### 第三期：高级策略
- E4 打板买入
- P6 换仓
- P7 调仓
- X3 板块退潮卖出
- I3 现金管理

## 六、与现有系统的关系

## 七、待专家确认的问题

1. 24 个原子操作归纳为 7+8+8+3 = 26 个信号类型，粒度是否合适？是否有过细或遗漏？
2. 信号层和操作层的边界：信号只管"做什么"、操作只管"怎么做"，这个切分是否合理？
3. 操作指令中的 `execution_window`（竞价/开盘/盘中/尾盘）是否应该由信号层决定而非操作层？
4. 止损/止盈从"固定规则"升级为"信号触发"后，原有的硬止损规则是保留为最后防线，还是完全由信号替代？
5. 做T的正T/反T是否值得作为独立信号？还是归入加仓/减仓？
6. 落地优先级的排序是否认同？
